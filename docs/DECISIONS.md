# Security implementation decisions

## Phase 1 — 2026-11-19

- Keep the existing separate trusted studio/untrusted animation WebViews and private MessagePort. There is no `addJavascriptInterface`; introducing one merely to add annotations would enlarge the attack surface. A closed schema now validates message names, keys, scalar types, sizes and ranges. File-opening remains limited to app-registered `content://` downloads and fixed system actions, not arbitrary Intent arguments or file paths.
- Offline is the default for both preview and service jobs. Known library/font CDN URLs can be answered with **packaged bytes**, not network access. Unknown resources fail closed with 403. File/content access and file-URL cross-access are explicitly disabled. Static `file:///android_asset/` aliases are normalized to the synthetic local HTTPS origin before execution; no broad `file:` CSP source is permitted. Only public packaged assets on a small allowlist may be intercepted; private files, arbitrary assets and the studio origin are never served to imported content.
- Online resources require native Persian confirmation. The UI checkbox alone grants nothing. Consent lasts for the current Activity/session; a started job captures the approved choice so background rendering can finish after Activity removal. A new Activity defaults offline. Imported JSON cannot set the native permission. Turning it off cannot undo requests already made while permitted. Changing it during a job is rejected without unlocking/cancelling the job.
- Online permits HTTPS resources and secure WebSockets, not HTTP/file/content navigation. The native resource interceptor also rejects URL userinfo and explicit ports; online opt-in is not a general-purpose browser. User code can send data to servers once online is approved. Do not claim complete device-wide network isolation: Safe Browsing and the platform's own services are outside imported-resource interception.
- CSP is inserted before any imported script, preserving an existing initial doctype. Inline scripts/styles and eval remain available because user-written JavaScript and the optional bundled Tailwind runtime are intended functionality. CSP is a network/embedding boundary, **not** a CPU sandbox. Service-worker requests have their own blocking native client/settings because they do not use a page WebViewClient. Child frames, workers, objects, forms and base-URL changes are blocked. Native navigation callbacks reject navigation; the browser UI also constrains iframe destinations. Existing content that relies on subframes/workers must be adapted; those avenues cannot be retained while claiming this boundary.
- Offline WebRTC constructors are disabled before imported code runs; an iframe/worker cannot create a fresh unrestricted realm under the policy. Keep Android System WebView updated. No claim of protection against a WebView/OS vulnerability is made.
- The standalone single-file UI embeds the already-bundled GSAP 3.12.5 bytes, including its original license header, to keep its preset executable without imported CDN requests. Native font/library assets are unchanged. Standalone offline documents must embed their own fonts/images; enabling online restores external resources. The trusted UI's mandated CDN tags remain in place and are served locally by Android.
- Explicitly enable Safe Browsing, deny third-party cookies/popups, and allow WebView debugging only when `ApplicationInfo.FLAG_DEBUGGABLE` is set. Do not use a generated BuildConfig dependency: the custom builder does not generate it. Release signing/minification and custom-builder build variants remain later-phase work.
- Renderer loss destroys/detaches the failed WebView, fails pending captures and cancels the service with a Persian error after cleanup. A failed trusted UI asks the user to close/reopen; no automatic reload loop. Native process-kill behavior is not claimed runtime-tested without an Android target.
- Do not change dimensions, frame count, timestamps, bitrate, conversion math, codec/muxer or buffer pipeline. Defer manifest/FileProvider changes, import limits/watchdogs, signing/CI supply chain, telemetry/privacy work, audio/queue/features and i18n to their explicit phases. Do not modify immutable published APKs/tags or ship a new release as part of this review phase.

## Phase 2 — 2026-11-19

- Use the actual AndroidX Core 1.13.1 FileProvider, not a new hand-written file-serving implementation. Retain the historical authority and root name for saved URI compatibility. A read-only subclass retains the generated-name restriction and denies modifications. Map only the Motion2Video Downloads folder; do not expose root storage or private cache/jobs. Keep MediaStore for newer Android versions. No new share UI is introduced before Phase 6.
- Inspect merged manifests. AndroidX adds Startup/ProfileInstaller components; its diagnostic receiver is explicitly non-exported, while in-process profile installation remains. Only the user-facing launcher may be externally launched. Keep explicit FGS type/permission declarations and existing backup/cleartext denial, with a system-CA-only network config.
- Preserve successful exports when public-save permission is denied: show the completed private result for later retry. Notification denial is informational and must not release a render lock. Keep runtime permission API decisions shared and boundary-tested.
- An OS timeout must stop the foreground service promptly. Do not join the render/codec worker on the main thread or clear its request prematurely. Capture the immutable request for cleanup, cancel pending frames/copies, release the wake lock and prevent stale publication after service destruction. Persist cleanup intent for interrupted private files. Process death/filesystem stalls still cannot guarantee synchronous cleanup or resume.
- Replace the SDK-only Python packaging implementation with a thin checked Gradle-wrapper entry point. AndroidX dependencies and genuine AGP resource shrinking need a consistent dependency/resource graph; duplicating Gradle resolution/minification in Python would make debug/release behavior diverge. Default debug builds and development-key overrides remain available. Full JDK17 is required; workspace-only proxy/trust configuration stays outside source.
- Release is explicitly non-debuggable, R8-minified and resource-shrunk, but unsigned. A temporary development-signed copy was used only for emulator QA; no production signing credentials or new public release are introduced. Keep rules are narrow: framework/manifest entry points and MessagePort method signatures, not whole app classes/fields. The release smoke test avoids app-private reflection so optimization remains exercised.
- Phase 2 runtime tests use Android 11/API30 software emulation. A manually invoked timeout handler there does not verify Android 15's scheduler/quota behavior. Physical devices, actual API26/28 permission flows and API33+ notification prompts remain outstanding. Phase 3 requires another confirmation.

## Phase 3

- Keep the requested 20 MiB HTML limit across native/browser/import/bridge/private-job boundaries. Admit unknown/generic/plain-text MIME only with a required HTML/HTM extension, since real document providers do not always return text/html. Reject explicit unrelated MIME, malformed UTF-8, binary NUL and invalid Unicode; do not guess legacy encodings. No ZIP/folder import was found or added.
- Keep existing render choices and the 45-second operation/120-second readiness waits. Add a two-hour monotonic service render deadline and a conservative Java heap budget (min(256 MiB, 85% VM maximum)) with preflight reserve; reject jobs rather than silently change output settings. These limits are not a whole-renderer/GPU memory sandbox. API 29+ may terminate a stuck app WebView renderer; older releases can only tear it down. Native codec/platform calls can delay cleanup.
- File reads run off the main thread. Provider streams are byte-bounded; an unresponsive third-party provider may still stall its import worker. No network/crash reporting or English entry language was introduced.

- Save editor HTML in existing app-private preferences, never in an Activity saved-state Bundle. Raising the admission limit to 20 MiB would otherwise risk Binder transaction failures on Activity recreation. Older small saved-state bundles still restore compatibly. Service Intents retain only the private request UUID.

## Phase 4

- Remove current APK binaries/checksums from the source tree without rewriting public history or tags. Distribute production APKs via GitHub Releases; keep CI debug artifacts clearly identified as contributor test artifacts. Preserve publishing automation through a separate guarded draft-publication job; default verification remains read-only. Only publication gets contents:write/actions:read, requires green CI for the exact tag plus trusted signer/native acceptance, and refuses published releases/extra assets. No production key enters CI or old tagged APK enters the source tree.
- Signing requires explicit `--release --sign` / Gradle opt-in. Environment inputs override an ignored owner-only local properties file; debug/unsigned builds do not read production secrets. Missing inputs fail closed. Only a short-lived throwaway QA key is generated for validation outside Git; no production identity is invented, shared, committed or published. Actual versioned names use Gradle APK metadata.
- Keep every bundled library/font byte unchanged to preserve rendering. Schema2 records versions/licenses and all hashes/sizes; actual font name tables and embedded GSAP are verified. Upstream family URLs do not imply known historical retrieval commits. GSAP's custom license/historical-grant questions remain concerns, not legal clearance.
- Isolate OWASP Gradle13.0.0 from AGP's classpath; scan the actual copied native runtime graph and bundled assets. CI fails for CVSS7+ or analysis/feed errors. No blanket suppression or disabled advisory feed is added to get a green build. NVD/CISA access failures are recorded as blocked scans, not vulnerability-free results. Npm audit includes dev tools; CI repository tokens default to read-only (write/read-actions only for explicit guarded publication), and all external actions are SHA-pinned.
- Private vulnerability reporting was verified disabled. The integration's enable request returned403, so no enabled/private-contact claim is made. Owner action in repository settings remains required; do not solicit sensitive reports in public issues. Continue other work without requesting redundant approval.
- Phase3 native acceptance remains unverified; Phase4 signed-build/host checks do not replace device testing or authorize publishing a hardened production APK. Phase5 requires another confirmation.

## Phase 5

- State the privacy boundary precisely: no first-party Android upload/telemetry/crash client was found, but online-consented imported code, standalone CDN startup, Safe Browsing/OS and chosen providers/tools prevent a blanket zero-off-device-traffic claim. Prove default imported-resource blocking and an opted-in synthetic POST with real TLS probes; do not equate that to Android packet capture.
- Install one console-suppressing WebChromeClient centrally for all native WebViews, in both build variants. Do not forward raw console message/source URLs or add verbose native diagnostics. Keep explicit debug-build WebView inspection; add no crash reporter. Request provider metrics opt-out without disabling Safe Browsing.
- Public error output uses only a bounded exact allowlist and fixed typed fallbacks. Never trust Persian-looking text or prefixes to distinguish private provider/codec messages. Filter legacy stored error/warning text when displayed; do not introduce a racing/destructive storage migration. Preserve output paths/URIs intentionally needed by Downloads, and document local draft/cache/history retention and user deletion controls.
- Remove speculative studio font preconnects while keeping the required standalone CDN resources, fonts, layout, motion and render settings. Only the studio HTML asset hash/size changes; other bundled asset hashes stay unchanged.
- Keep optional desktop FFmpeg encoding/audio/container arguments unchanged. Default diagnostic streams go to DEVNULL and failures do not dump the command; --debug explicitly restores local diagnostics. External FFmpeg protocols/OS logging are not claimed to be controlled by Android policy.
- Native logcat/network/provider acceptance remains unverified due to the previously broken emulator. Compiled manifest flags/callback fixtures and host checks are scoped evidence, not proof of provider behavior. Phase4 advisory-feed/admin blocks remain; no production APK is published. Stop before Phase6.

### Phase 6a
Capability fallback is a proposal requiring explicit application and a new render action. Only successful codec probes are cached; no runtime benchmark or added work per frame. Production signing and publication remain owner-only.
