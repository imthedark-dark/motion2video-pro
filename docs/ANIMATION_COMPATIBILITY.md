# Imported animation compatibility audit

Comparison: published tag `v1.4.1` and `feature/phase-6` at `38f99dd`. The relevant sources are MainActivity, StudioActivity, OffscreenStage, ImportedContent, StageAssets, WebViewSecurity, the manifest and motion-clock.js.

| Area | Public tag → Phase 6 | Effect on normal content |
| --- | --- | --- |
| Document loading | Both native stages use `loadDataWithBaseURL` at `https://motion.local/`. Phase 6 adds CSP ahead of the markup and translates packaged `file:///android_asset/` URLs to the synthetic HTTPS origin. Both versions' clock/font injection prepended code before the doctype when there was no explicit closing head. | Source base is stable. The former headless path put standards-mode fixtures into quirks mode. This branch preserves the doctype and shares preparation between both stages. |
| CSP and local bytes | The tag had no imported CSP. Phase 6 allowed inline script/style, data/blob scripts and images/media, data fonts, but disabled all offline connections and omitted blob fonts and data/blob stylesheets. | Chromium reproduces an aborted setup at `fetch(data:…)` with a `connect-src` violation. A loader can fail before its first frame even though the same URL works as an image. Blob fetches and generated font/style URLs require their own directive. |
| Request interception | The old offscreen loader matched bundled libraries by basename even on arbitrary hosts; the old preview had separate mappings for bundled files. Unhandled requests could use WebView networking. Phase 6 shares the strict synthetic-origin and recognized CDN aliases, exact bundled fonts and known Google Fonts families. Other URLs receive 403 offline; `setBlockNetworkLoads(true)` provides another boundary. | Known local GSAP, plugins, Lottie, Three.js and fonts work through their documented aliases. Unknown CDN URLs, different script filenames such as `three.module.js`, relative companion files, arbitrary fonts/textures, and external resources fail offline. The explicit HTTPS opt-in remains required for external dependencies. Bundled library aliases use the shipped versions. WebView calls interception for data URLs, so the old catch-all 403 could also reject them at that layer. Chromium WebView does not dispatch blob URLs to this callback. The branch delegates inline data bytes to WebView. |
| File, URL and storage settings | File access, content access and mixed content were already off. Phase 6 explicitly disables file-origin cross-access, popups and third-party cookies, blocks service-worker network/content/file access and starts offline. Imported storage stays disabled and trusted studio storage stays enabled. Top-level navigation was already rejected. | Arbitrary device files, WebRTC and online fetches/beacons/sockets are unavailable offline. Workers, service workers, nested frames, forms and plugins remain outside the supported import model. The Studio CSP independently protects the trusted document. |
| JavaScript and bridge | Both versions separate trusted and imported documents into two native WebViews. Studio has the native MessagePort and the offscreen WebView has a frame-clock port. There was no JavaScriptInterface. Phase 6 adds closed schemas and size/type limits and isolates content under its own policy. | Imported scripts can still run, including inline scripts, Canvas, WebGL, main-thread embedded WebAssembly and requestAnimationFrame. The clock source was unchanged between the tag and Phase 6. Render-time sampling is driven by the clock. External module dependencies, WASM files or workers face the resource/worker rules above. |
| Views, graphics and lifecycle | Both versions created a hardware-layer preview plus a separate Studio WebView. The native editor's iframe was empty during native preview and standalone web uses it for the imported document. Offscreen export adds a private-display WebView, software for 2D and hardware/PixelCopy with GPU selected. Neither version set renderer priority, offscreen preraster, or a multiprocess override. Phase 6 added explicit Safe Browsing, debug-only WebView debugging, a console sink, renderer-exit handlers, memory limits and watchdog termination. | There was no default layer change to explain the report. Large textures and filter effects are not forbidden by CSP, but device GPU limits, driver bugs, memory pressure or a blocked main thread can cause a context loss, kill, or 45-second watchdog exit. A phone's total RAM alone cannot distinguish these. The Studio formerly started an inherited preview load before the trusted UI drove the first preview. The branch skips that extra load and waits for fonts used by the document instead of explicitly forcing six unrelated font families. |
| Input and readiness | Phase 6 rejects invalid UTF-8, unsupported import type/extension, and HTML over 20 MiB. Both versions observe page/font readiness, with Phase 6 wrapping preparation and capture in deadlines. | An invalid import should return an input error. A blocked resource may fail initialization, show an incomplete animation, or hit a readiness timeout. A CSP violation alone is a JavaScript/resource error and does not establish why Android reported renderer process death. |

The new Chromium test uses Java's production document preparation, the same origin, the shipped clock and libraries, and a route shim for the native asset responses. It reads actual Canvas and WebGL pixels, checks particle movement, and fails on console errors, unexpected requests or CSP violations. Android's interception callback, vendor WebView, virtual-display compositor, and actual renderer exits require device verification.

On the phone, open **درباره** to record the WebView package and version. Use the same HTML offline in normal preview and in **حالت سازگاری**. Software preview is for Canvas 2D and may omit WebGL. It leaves the export capture mode selectable. Retry recreates the activity and reloads the draft. The recovery dialog links to Persian troubleshooting. On a debug APK and USB debugging, capture the single fixed-schema event after reproducing:

```sh
adb logcat -d -s Motion2VideoWebView:D
```

A `preview-timeout` event records app watchdog intervention. A `renderer-exit` event includes Android's `didCrash` and renderer priority at exit. `didCrash=false` indicates a killed process, and Android's API does not establish that low memory was the cause. The policy, layer settings, first error category and CSP directive are hints. Arbitrary animation text can influence the category but is never included in the event. With the exact HTML or diagnostics, verify the actual Xiaomi failure, test both retry buttons with a renderer shared by two views, and try both capture modes on the device.

## Host verification

Before the fix the fixture stopped at its first embedded texture fetch with `connect-src` and `TypeError: Failed to fetch`. After the fix it rendered nonempty Canvas and WebGL frames, moved points across frames, and reported a dispatched WebGL context-loss event. The fixture reported zero console errors, failed resource requests or CSP violations. The separate security probe recorded zero offline TLS hits, including no worker, frame or navigation request. Debug and unsigned R8 release builds, UI and clock tests, 72 byte-identical YUV cases, 246 bridge/request cases, input/feature/privacy checks, bundled hashes and compiled manifest verification all passed.
